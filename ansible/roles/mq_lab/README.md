# mq_lab

**Example / evaluation only; not approved for productive operation. Before
productive use, clarify the license question with IBM.**

Rocky Linux 9 amd64 lab hosting a pinned MQ 9.4 developer image via rootful
Podman inside an unprivileged LXC. Installs Podman, OpenSSL, firewalld and vim;
does not use the Debian-only baseline/Podman roles.

Managed files: `/etc/bergen-mq-lab/` (VFS configuration, protected Vault secret
inputs, private evaluation CA/server certificates),
`/etc/containers/systemd/bergen-mq-lab.container`,
`/var/lib/bergen-mq-lab/identity.json` and persistent `mqm/` data. Public CA and
an ignored connection example are copied to the controller.

Service: `bergen-mq-lab.service` generated by Quadlet, with journald container
logs. Local authenticated REST readiness uses verified TLS. Source-specific
firewall rules permit controller HTTPS; MQ client traffic requires explicit
opt-in. Host networking avoids nested Podman DNAT/firewall bypass.

Required secrets: `mq_lab_admin_password`, `mq_lab_app_password` from Vault.
Explicit gates: `mq_lab_confirm_test_only: true`,
`mq_lab_license_acceptance: accept`. Neither is an approval for production.

No automatic persistence adoption, QMGR renaming, image upgrades/downgrades,
certificate rotation, permission bypass or destructive cleanup. See
[MQ evaluation guide](../../../docs/MQ-LAB.md) for rollout, safety boundaries
and outstanding real-host acceptance.
