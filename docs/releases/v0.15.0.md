# Bergen Platform v0.15.0 — Bergen-AI family groups and chat profiles

**Release date:** 2026-10-20

This release versions the Bergen-AI configuration already deployed to the existing Open WebUI 0.10.2 instance. It adds guarded, reviewable Ansible tooling and a canonical as-operated runbook. Merging the source does **not** redeploy the service or grant new permissions.

## Functionality

- Synology OIDC mapping into three existing, location-specific family roles (`Familie`, `Eltern`, `Kinder`) through the protected existing Podman/Quadlet environment. The group sync flag is enabled, while group creation and automatic role management stay disabled.
- Four private model profiles: two parent-only (general Qwen and Mistral language assistant), two child-only (Qwen learning companion and Mistral language trainer).
- Child model system prompt includes `Vorsagen untersagt` and encourages independent learning. It is a pedagogical instruction, not a substitute for access control.
- Independent read-only SQLite/model ACL audits, tokenless runtime readiness checks and version-pinned approved model API deployment using an existing legitimate admin session JWT. No new API-key subsystem required.
- **Idempotent reruns:** when all four private profiles exactly match the desired state, the approved model Apply returns `ALREADY_STAGED`, `CREATED=0`, `CHANGED=False`; changes/rollback still demand current-state approval and fingerprint checks.

## Production evidence

On 2026-10-20, protected Ansible Apply reported `PRIVATE_PROFILES_STAGED`, `CREATED=4`, no error. Independent audit found `REGISTERED_MODELS=4`, `MODEL_GRANTS=4`, `PUBLIC_READ_GRANTS=0`, `CHILD_RAW_MODEL_READ_GRANTS=0`, `UNKNOWN_OR_FOREIGN_MODEL_GRANTS=0`. The existing parent account showed only the two parent assistants in the mobile UI. CI regression tests for repeat-apply idempotence passed; **the second Apply has not yet been performed live**.

## Known limitations and deferred security gates

- Positive child SSO/login and negative **direct model API** tests for child, parent, pending and revoked sessions are **not attested**.
- Open WebUI 0.10.2 missing/empty group claims, group revocation and already active sessions are **not proven fail-closed**. Do not claim full end-to-end isolation.
- The operator supplied the protected backup-approval flag, but this release log has **no independent evidence of a successful SQLite/WAL restore test**.
- Distinct display descriptions for each of the four profiles are *drafted*, but were not installed as per-model metadata. The installed generic description remains unchanged.
