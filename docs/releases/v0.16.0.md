# Bergen Platform v0.16.0 — Paperless-AI: regulärer Posteingang

**Release date:** 2026-10-21

This release records a **production deployment already completed** on
2026-10-21. Publication and source integration do **not** redeploy the
existing timer, rerun classification, reset the protected SQLite journal,
remove Inbox tags, or authorize extra data access.

## Delivered functionality

- Version-pinned, local-only native Paperless-ngx **3.3.0** / Ollama-Qwen
  AI metadata cataloguing, using the existing `bergen-ai-catalog.timer`
  after the normal Paperless import, OCR and classical matching.
- **All documents** whose native Paperless Inbox flag
  `Tag.is_inbox_tag=True` is set and whose `Document.added` import
  timestamp is **at or after 2026-10-01 00:00 Europe/Berlin**.
  **No restriction by document owner, active status, administrator status,
  group membership, sharing ACL or document-ID watermark.**
- One eligible document per five-minute timer run; minimum OCR
  availability and unversioned-document safety prerequisites.
- Safe local inference: v2 deliberately avoids retrieval of other
  documents' OCR into the LLM prompt, including the otherwise
  unrestricted `user=None` context. Group/owner/global permissions are
  used **only when resolving existing taxonomy**, never to decide
  which documents enter the workflow. No new taxonomy objects.
- Guarded write-back of eligible machine-imported titles, empty
  correspondent/document-type fields and additive existing tags.
  Native Paperless review Notes are system-attributed
  (`Note.user=None`) without pretending to be an owner.
- **Never** remove the Inbox tag, change document ownership/group ACL,
  original/archive files or manually established metadata. All
  recorded journal states remain terminal to the timer: no automatic
  retry of earlier successes, reviews or indeterminate outcomes.
- Read-only aggregate Ansible audit of the exact import-date scope,
  runtime status and private SQLite processing journal. Prior unsafe
  parallel v2 cutover instructions were disabled.

| 08:04, independent v2 audit | `ALL_INBOX_ADDED_FROM_OCT1=38`, `OCR_READY_UNVERSIONED=38`, `READY_UNJOURNALIZED=0`; `ok=9 changed=0 failed=0` |

| 08:04, Paperless native Notes | 32 v2 system-attributed Notes counted |

**Delta actually demonstrated:** All **32** previously unjournalized
eligible documents were processed after the v2 cutover:
31 additional `APPLIED`, one additional `NO_CHANGE`, no new
`REQUIRES_REVIEW`. The four existing review states were retained,
not retried. All 38 eligible records are **journalized**, but only
34 have success states. These are technical journal outcomes, **not**
proof that every AI suggestion is substantively correct.

## Known limitations and deferred work

- Four historical `REQUIRES_REVIEW` documents need a separate,
  explicitly authorized manual case audit and reconciliation.
- Content review of all 32 Notes and metadata changes, including
  user-interface visibility and taxonomy accuracy, is **not attested**.
- The systemd service returned success but structured Bergen-AI
  outcome frames were not observed in the earlier v1 service journal;
  post-v2 journald transport has **not** been positively verified.
  The private SQLite journal and independent read-only audit
  are the accepted current evidence.
- Original backup approval was operator-supplied; a verified
  restore test is **not attested**.
- Effective unauthenticated Ollama TCP/11434 negative-client isolation
  is **not fully demonstrated**. Keep that hardening separate.
- The one-way v1→v2 upgrade is **not** a proven idempotent
  v2→v2 reapply; no second live upgrade execution is attested.
- No automatic Inbox-tag removal, source-file deletion, model
  retraining or unjournalized replay was performed as part of
  source/release publishing.
